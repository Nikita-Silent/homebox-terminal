# Терминал склада для Homebox

Сенсорный терминал для перемещения оборудования между складами, помещениями и полками поверх
[Homebox](https://github.com/sysadminsmedia/homebox). Одна задача: найти или отсканировать вещь, выбрать полку
и количество, подтвердить. Всё записывается в Homebox сразу. Homebox остаётся главной базой, терминал своей копии
склада не хранит.

Рассчитан на складской ПК или моноблок с сенсорным экраном 1024×768 или 1280 по ширине (браузер в полноэкранном режиме) и USB-сканером штрихкодов. Работает и на планшете,
и на обычном компьютере. Интерфейс только на русском, чёрно-белый, с крупными кнопками под работу в перчатках.

## Что умеет

- **Поиск** по названию, модели, серийному номеру и UID (`000-011`), скан этикетки Homebox USB-сканером
  или камерой, выбор из дерева складов, если название неизвестно.
- **Перемещение** целиком и частью количества, объединение с таким же товаром на целевой полке.
- **Корзина:** несколько вещей на одну полку за один раз.
- **Надёжность:** сервер перечитывает запись перед изменением, повторная отправка не выполняет операцию дважды,
  после сбоя сети или перезапуска операция доводится до конца. Количество не уходит в минус и не теряется
  при частичном перемещении.
- **Вход по PIN** с экранной клавиатуры, автовыход через 15 минут простоя.
- **Журнал перемещений** для администратора: кто, что, сколько, откуда и куда.
- **Экранная клавиатура:** системная на таком терминале не появляется, потому что USB-сканер считается подключённой
  клавиатурой.
- **Статус связи с Homebox** в верхней панели: на связи, недоступен, ключ не принят, непроверенная версия.

## Как устроено

```
браузер терминала ──► сервер терминала (Nuxt/Nitro) ──► Homebox API
                         │
                         └── SQLite: журнал операций, сотрудники, сессии
```

- Браузер ходит только на сервер терминала. API-ключ Homebox хранится на сервере и в браузер не попадает.
- Все изменения в Homebox делаются одним ключом терминала. Кто сделал операцию, видно в журнале терминала,
  а не в истории Homebox.
- В SQLite лежат журнал операций (он же журнал для повторов после сбоя), сотрудники с хешами PIN и сессии.
  Подробно: [ADR 004](logic/decisions/004-sign-in-and-journal.md).

## Требования

- **Homebox 0.27.0.** С другими версиями терминал запустится, но в логе и на плашке будет предупреждение
  «не проверен». Особенности API: [docs/homebox-api-notes.md](docs/homebox-api-notes.md).
- Docker и Docker Compose для запуска, либо Node.js ≥ 24.15 и pnpm 11 для разработки.

## Запуск

### 1. API-ключ Homebox

Терминалу нужен API-ключ пользователя Homebox (вида `hb_…`). Homebox выдаёт ключи, только если у него задан
`HBOX_AUTH_API_KEY_PEPPER` (не короче 32 байт). Ключ создаётся запросом от имени пользователя:

```bash
HB=http://homebox:7745
TOKEN=$(curl -s "$HB/api/v1/users/login" -H 'Content-Type: application/json' \
  -d '{"username":"терминал@example.com","password":"…"}' | jq -r .token)
curl -s "$HB/api/v1/users/self/api-keys" -H "Authorization: Bearer ${TOKEN#Bearer }" \
  -H 'Content-Type: application/json' -d '{"name":"terminal"}' | jq -r .token
```

Лучше завести для терминала отдельного пользователя в нужной группе Homebox.

### 2. Настройки

```bash
cp .env.example .env
```

| Переменная | Что задаёт |
|---|---|
| `NUXT_HOMEBOX_BASE_URL` | Адрес Homebox без `/api`, например `http://homebox:7745` |
| `NUXT_HOMEBOX_TOKEN` | API-ключ из шага 1 |
| `NUXT_ADMIN_NAME`, `NUXT_ADMIN_PIN` | Первый администратор (PIN 6–8 цифр). Создаётся при старте, если активного администратора нет |
| `NUXT_ALLOWED_HOSTS` | Имена и адреса, по которым открывают терминал, через запятую: `terminal.local,192.168.1.20:3000`. Защита от DNS rebinding; в продакшене задать обязательно |
| `NUXT_JOURNAL_PATH` | Файл SQLite. В Docker уже указывает на том `/data` |
| `NUXT_JOURNAL_RETENTION_YEARS` | Сколько лет хранить журнал, по умолчанию 5 (`0` — всегда). Незавершённые операции не удаляются |
| `NUXT_SESSION_IDLE_MINUTES` | Автовыход после простоя, по умолчанию 15 минут |

### 3. Docker Compose

```bash
docker compose up -d --build
```

Терминал откроется на порту `3000`. Дальше:

1. Войти администратором, на странице «Сотрудники» завести сотрудников с PIN.
2. На складском ПК открыть терминал в браузере на весь экран (кнопка справа в верхней панели или режим киоска).

Журнал и сотрудники лежат в томе `journal`. Резервная копия — это файл `journal.sqlite` из него. Рядом могут
лежать `-wal` и `-shm`: копируйте вместе с ними или через `sqlite3 journal.sqlite ".backup копия.sqlite"`.

### Сканер и камера

- **USB-сканер** должен работать в режиме клавиатуры (HID) и заканчивать код Enter. На экранах поиска, складов,
  карточки, перемещения и корзины сканировать можно сразу, не нажимая на поле поиска. Понимаются этикетки Homebox (ссылки на вещь, полку, `/a/<UID>`)
  и UID вида `000-011`.
- **Камера** в браузере работает только по HTTPS или на том же компьютере (`localhost`). По обычному HTTP
  в локальной сети терминал предложит USB-сканер.

### Проверка

`GET /api/health` открыт без входа и отвечает, видит ли терминал Homebox:

```json
{ "ok": true, "homebox": "ok", "homeboxConfigured": true, "homeboxVersion": "0.27.0", "homeboxTested": true }
```

`homebox` бывает `ok`, `unreachable`, `unauthorized` (ключ не принят) и `not_configured`.

## Разработка

```bash
pnpm install
cp .env.example .env              # адрес и ключ тестового Homebox
pnpm dev                          # http://localhost:3000
```

Тестовый Homebox для разработки:

```bash
cp .env.homebox.example .env.homebox   # задать HBOX_AUTH_API_KEY_PEPPER
docker compose -f docker-compose.homebox.yml up -d   # http://127.0.0.1:7745
```

Пользователь регистрируется в веб-интерфейсе Homebox, ключ создаётся как в шаге 1. Данные лежат в `.data/homebox`.

| Команда | Что делает |
|---|---|
| `pnpm dev` | Сервер разработки |
| `pnpm build` | Продакшен-сборка в `.output` |
| `pnpm lint` | ESLint |
| `pnpm typecheck` | Проверка типов приложения, сценариев и e2e |
| `pnpm test` | Unit-тесты и сценарии бизнес-правил (vitest) |
| `pnpm test:logic` | Только сценарии из `logic/features` |
| `pnpm test:e2e` | Сборка и сквозные тесты в браузере против настоящего Homebox в Docker |

Подробно про тесты: [docs/testing.md](docs/testing.md).

### Структура

```
app/                 интерфейс (Nuxt 4, Vue, Tailwind, shadcn-vue)
  pages/             экраны: поиск, карточка, перемещение, итог, корзина, склады, вход, журнал, сотрудники
  components/        панель, экранная клавиатура, сканер камерой, выбор полки, статус Homebox
server/              сервер терминала (Nitro)
  api/               API для интерфейса
  homebox/           клиент Homebox API
  services/          перемещения (сага с журналом) и вход по PIN
shared/types/        типы, общие для сервера и интерфейса
logic/               правила перемещения: сценарии на русском (Gherkin) и решения (ADR)
e2e/                 сквозные тесты (Playwright)
docs/                особенности Homebox API, спецификация 0.27.0, тесты
```

- [logic/decisions/](logic/decisions/) — почему сделано именно так.
- [docs/homebox-api-notes.md](docs/homebox-api-notes.md) — проверенное поведение Homebox API и обходы его особенностей.

### Обновление Homebox

1. Поменять `image` в `docker-compose.homebox.yml` и `docker-compose.e2e.yml`.
2. Прогнать `pnpm test:e2e`.
3. Сверить swagger новой версии с `docs/homebox-0.27.0-swagger.json`, поправить `docs/homebox-api-notes.md`.
4. Добавить версию в `TESTED_HOMEBOX_VERSIONS` (`server/utils/homebox-version.ts`).

## Ограничения

- Терминал считает местом вещи её родителя в Homebox. Вещь, вложенная в другую вещь (кабель в кейсе),
  показывается внутри кейса, а перемещение на полку вынимает её из кейса.
- Список имён сотрудников виден на экране входа любому, кто открыл терминал в сети.
