# Homebox 0.27.0 API — проверенное поведение

Проверено на тестовом экземпляре (`docker-compose.homebox.yml`): 0.26.2 — 2026-10-14, 0.27.0 — 2026-10-20.
Полная спецификация: `docs/homebox-0.27.0-swagger.json` (`backend/app/api/static/docs/swagger.json` в теге `v0.27.0`).
Терминал работает и с 0.26.2: эндпоинты, которыми он пользуется, не изменились.

## Модель данных

- В 0.26 вещи и локации — это одна сущность **entity** (`/v1/entities`).
  Различаются типом: `entityType.isLocation`. По умолчанию есть типы `Location` и `Item`.
- Иерархия задаётся через `parentId`. Item лежит в локации, локация — в другой локации.
- **С 0.27.0: `locationId`** — отдельное место хранения у вещи, вложенной в другую вещь
  (`parentId` → вещь, а лежит она на другой полке). Если `parentId` — локация, `locationId` пуст.
  В ответе GET: `locationId` — только собственное место (иначе нет), `location` — вычисленное
  (своё или ближайшая локация-предок).
  - `PATCH {parentId: <локация>}` сбрасывает `locationId`. Перемещение терминала на полку им не мешает.
  - `PUT` без `locationId` его **стирает** (как и всё непереданное).
  - `duplicate` копирует `locationId` источника.
  - Терминал считает местом `parent` и вещи с собственным `locationId` показывает внутри родителя,
    а не на полке хранения.
- `assetId` (формат `000-006`) есть и у Item, и у локаций. Поиск по нему: `GET /v1/assets/{assetId}`.
- Дерево локаций: `GET /v1/entities/tree` (`withItems=true` — вместе с вещами).
- Поиск: `GET /v1/entities?q=&parentIds=&page=&pageSize=`. Возвращает только вещи, без локаций.
  `parentIds` — только прямые потомки; с 0.27.0 ещё и вещи, у которых `locationId` равен одному из них.
  `pageSize=1000` принимается.
  - 0.26.2: `q` ищет по названию, модели и серийному номеру, но **не** по `assetId`.
  - 0.27.0: `q` ищет ещё по описанию, производителю, заметкам, тегам и кастомным полям;
    `#000-024` — по `assetId`, кавычки — точная фраза. Новые параметры: `entityTypeIds`, `orderBy`, `orderDirection`.
- **Ошибка Homebox 0.26.x: `q` не находит кириллицу.** «Кабель» не находит «Кабель UTP cat6», а «UTP» — находит.
  Вероятная причина: запрос приводится к нижнему регистру в Go, а колонка — функцией SQLite `lower()`, которая понимает только ASCII.
  В 0.27.0 исправлено: «кабель», «КАБЕЛЬ», «Каб» находят «Кабель 08».
  Обход в терминале остаётся, чтобы работать с обеими версиями: поиск по названию и `assetId` идёт по локальной копии
  списка вещей (`server/utils/item-index.ts`, обновляется раз в 30 с).

## Авторизация

- API-ключи: `POST /v1/users/self/api-keys` → `token` вида `hb_…`.
  Заголовок: `Authorization: Bearer <token>`.
- Для работы API-ключей сервер Homebox требует `HBOX_AUTH_API_KEY_PEPPER` (≥ 32 байт), иначе не стартует.

## Изменение данных

| Операция | Поведение |
|---|---|
| `PATCH /v1/entities/{id}` | Меняет только переданные `parentId`, `locationId` (0.27.0), `quantity`, `tagIds`, `entityTypeId`. Остальные поля не трогает. **Безопасно.** С 0.27.0 — в одной транзакции. |
| `PUT /v1/entities/{id}` | **Полная замена.** Непереданные поля обнуляются. Проверено: PUT без `assetId` стирает `assetId`. **Не использовать** без полного набора полей из свежего GET. |
| `POST /v1/entities/{id}/duplicate` | Создаёт копию в **той же** локации с **тем же** количеством. Копирует поля модели, заметки, кастомные поля (`copyCustomFields`), вложения (`copyAttachments`), журнал обслуживания (`copyMaintenance`). `copyPrefix` добавляется в начало имени; пустой префикс заменяется на `Copy of `. Копия получает новый `assetId`. |

## Чего в API нет

- Транзакций и пакетных операций.
- Оптимистичной блокировки (версий, `If-Match`). `quantity` в PATCH задаётся абсолютным значением, а не изменением.
- Полноценной проверки количества: **дробное** (`1.5`) `quantity` принимается всегда, **отрицательное** (`-5`) —
  в 0.26.2; 0.27.0 его отклоняет, но ответом `500 Unknown Error`, а не 400. Валидация полностью на нашей стороне.

## Следствия для частичного перемещения

- Перемещение целого Item — один `PATCH {parentId}`.
- Частичное через создание копии: `duplicate` → `PATCH копии {quantity, parentId}` → `PATCH источника {quantity}`.
  Между шагами общее количество временно неверное, поэтому нужен журнал (сага).
- Частичное с объединением в существующий Item на целевой полке: `PATCH источника` + `PATCH цели`. Без создания сущностей.
- Гонку двух терминалов на одном Item API исключить не позволяет: только перечитывание перед записью.

## Фото

- У записи `imageId` — основное фото (primary photo attachment) и `thumbnailId` — уменьшенная копия
  ~500 px в WebP, которую Homebox делает сам вскоре после загрузки. Обе отдаются тем же
  `GET /v1/entities/{id}/attachments/{attachmentId}`. До генерации миниатюры `thumbnailId` пуст.
- Тип вложения «photo» не проверяет содержимое: в тестовой базе есть «фото» с `text/plain`,
  а SVG со скриптом принимается. Прокси терминала отдаёт только растровые форматы.
