# 001. Частичное перемещение — сага с журналом

**Дата:** 2026-10-14 · **Статус:** принято

## Контекст

В Homebox 0.26.2 нет транзакций, пакетных запросов и оптимистичной блокировки. Количество в `PATCH`
задаётся абсолютным значением. Частичное перемещение требует 2–4 запросов; сбой между ними оставляет
данные несогласованными. ТЗ требует не терять оборудование и не выполнять операцию дважды.

## Решение

- Операция — сага из шагов. Перед каждым запросом шаг записывается в журнал (SQLite, `node:sqlite`,
  файл в Docker-томе) со статусом `sent` и ожидаемыми значениями «до» и «после».
- Шаги, которые добавляют количество на цель, идут раньше шагов, которые списывают с источника.
- Если ответ потерялся, при повторе свежее значение сравнивается с «до» и «после»: «после» — шаг
  выполнен, «до» — повторить, иное — статус «требует проверки», данные вслепую не пишутся.
- Копия при разделении создаётся с меткой `[hbt:<opId>]` в имени, чтобы найти её после сбоя;
  в конце метка снимается.
- Идентификатор операции (`opId`) генерирует терминал. Повтор с тем же `opId` возвращает сохранённый
  результат или продолжает прерванную операцию.
- Незавершённые операции сервер доводит сам: при старте и раз в 30 секунд.
- Операции над одной записью выполняются по очереди (блокировка в процессе сервера).

## Последствия

- Нужен постоянный том для журнала: без него гарантии теряются при пересоздании контейнера.
- Если запись правят в веб-интерфейсе Homebox в те же секунды, когда идёт операция, полной защиты нет:
  API этого не позволяет. Такие случаи получают статус «требует проверки».
- Сервер терминала должен быть один (блокировка — в памяти процесса).
