# Логика работы терминала

Здесь описано, **как** терминал меняет данные в Homebox. Это источник правды по поведению:

- `features/` — сценарии на русском (Gherkin). Каждый выполняется как тест против настоящего кода.
  Если код ведёт себя не так, как написано, `pnpm test` падает.
- `decisions/` — почему сделано именно так (короткие записи о решениях, ADR).
- `steps/` — словарь фраз, из которых составляются сценарии, и их связь с кодом.

Код логики: `server/services/transfers/`. Особенности Homebox API: `docs/homebox-api-notes.md`.

## Правила перемещения

Запись с **1 шт.** — поштучный учёт (у вещи своя история). Запись с **больше 1 шт.** — количественный учёт.

| Что переносят | На целевой полке есть такой же товар (> 1 шт.) | Такого нет, или там поштучная запись |
|---|---|---|
| Поштучную запись (1 шт.) | Переезжает целиком, **не объединяется** | Переезжает целиком |
| Всё количество записи (> 1 шт.) | Количество **добавляется** к той записи, исходная **удаляется** | Переезжает целиком |
| Часть количества | Количество **добавляется** к той записи | Создаётся **новая запись**-копия со всеми данными |

- «Такой же товар» — совпадают производитель и модель; если модели нет — точное название.
- Если подходящих записей несколько, терминал не выбирает сам — выбирает сотрудник.
- Вместо объединения сотрудник всегда может выбрать «Записать отдельной строкой».

Сценарии: [01-whole](features/01-whole.feature), [02-partial](features/02-partial.feature),
[03-merge](features/03-merge.feature).

## Проверки и надёжность

- Перед перемещением сервер перечитывает запись из Homebox. Если количество или полка уже не те,
  что видел сотрудник, операция отклоняется. → [04-validation](features/04-validation.feature)
- У каждой операции свой идентификатор: повторная отправка не выполняет её второй раз.
- Каждый шаг записывается в журнал до запроса в Homebox. После сбоя операция доводится до конца.
  Сначала добавляем на цель, потом списываем с источника: сбой даёт излишек, а не потерю.
  → [05-reliability](features/05-reliability.feature), [ADR 001](decisions/001-transfer-saga.md)

## Как пользоваться

```sh
pnpm test:logic          # только сценарии
pnpm test                # все тесты
```

**Добавить сценарий.** Опишите случай в подходящем `.feature`, используя фразы из `steps/transfer.steps.ts`
(список ниже). Если нужной фразы нет — её надо добавить в `steps/`, иначе тест упадёт с ошибкой
«Undefined step». Новое правило сначала записывается сценарием, потом реализуется в коде.

**Поменять правило.** Сначала исправьте сценарий и `README`, затем код — до тех пор тесты красные.

### Фразы

Дано:
- `на полке "A-01" лежит "Название" 5 шт.`
- `на полке "A-01" лежит "Название" 5 шт., производитель "D-Link", модель "DGS-1005C"`
- `у "Название" на полке "A-01" есть заметка "…"` / `есть поле "Инв. номер" = "INV-42"`
- `в Homebox у "Название" на полке "A-01" стало 7 шт.` — кто-то поменял запись в Homebox
- `связь с Homebox оборвётся после шага "…"` — шаги: создание копии, добавление на целевую полку,
  списание с исходной полки, удаление исходной записи

Когда:
- `сотрудник выбирает перенос 5 шт. "Название" с полки "A-01" на полку "B-01"` — экран подтверждения
- `сотрудник переносит 5 шт. "Название" с полки "A-01" на полку "B-01"` — подтверждает выбор по умолчанию
- `… на полку "B-01" отдельной записью` / `…, видя в карточке 50 шт.`
- `терминал повторно отправляет ту же операцию`
- `два терминала одновременно переносят по 30 шт. "Название" с полки "A-01" на полку "B-01"`
- `сервер доводит незавершённые операции`

То:
- `операция "выполнена"` / `"ждёт завершения"` / `"требует проверки"` / `"не выполнена"`
- `операция отклонена с сообщением "…"` / `второй терминал получает отказ "…"` / `сотрудник видит сообщение "…"`
- `на полке "B-01" теперь "Название" 35 шт.` / `на полке "A-01" нет "Название"`
- `на полке "B-01" 2 отдельные записи "Название" по 1 шт.`
- `всего "Название" 50 шт.` — сумма по всем полкам
- `перенесена та же запись` / `исходная запись удалена из Homebox`
- `у "Название" на полке "B-01" заметка "…"` / `поле "…" = "…"`
- `терминал предлагает перенести запись целиком` / `создать новую запись` /
  `добавить к записи, где сейчас 25 шт.` / `просит выбрать одну из 2 подходящих записей`
